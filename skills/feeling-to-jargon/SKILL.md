# Feeling to Jargon

Feeling to Jargon 帮助用户把模糊感受翻译成专业术语，再按需补全成可执行的提示词。

## 安装后的唯一入口

将本文件所在目录记为 `SKILL_DIR`，**不依赖当前项目工作目录**。用 `python3 <SKILL_DIR>/scripts/query.py "用户原话" --format agent` 调用；`<SKILL_DIR>` 替换为本 Skill 的实际绝对目录。运行包随 Skill 安装，无需另找源码仓库、联网或安装依赖。

默认使用 `--format agent`：保留完整知识/约束/依赖，只去除重复解释与内部诊断。定位错误或测量读取时才使用 `--format full`。不要把查询原始 JSON 直接当作面向用户的回答。

## 检索、组合与交付协议

五级体系 `领域 → 子域 → 意图 → 叶子 → 条目` 是知识组织与引用结构，不是 CLI 必须按层顺序扫描的流程。领域是归属；意图、知识类型和平台是维度，不枚举全部分类组合。

1. **先用原话调用 CLI**，不要要求用户知道术语：`python3 <SKILL_DIR>/scripts/query.py "用户原话" --format agent`。
2. CLI 内部读取生成的检索投影与 runtime 元数据，先匹配四个现有场景；明确或部分命中复用流程，无场景时进行通用词法检索。它随后组合叶子/共享协议，检查预算与归属，输出交付结构。这是有限启发式，不是真正的语义模型；不把排序分数叫概率。
3. **先回答术语，再问必要问题**：读取 `candidate_terms`，把简短感觉展开成几项有来源的术语及白话解释，明确哪些只是条件性建议。只讲与当前感觉相关的 `terms`，不要把候选条目的完整名称/所有变体当作推荐清单。`knowledge_loaded=false` 只够解释/澄清，不足以输出实现参数；不要因此加载所有候选。对象不明时用“如果你指的是……”给方向，再问一个影响选择的问题，不能只回一句“请说清楚”。随后阅读 `explanations / coverage / clarifications`，区分原文证据与建议。“稳定”不意味着并发/幂等全要，“很多人用”只能建议核对并发；“有质感”不能直接决定风格。只问改变方案的问题，已在原话或 `context.answers` 中提供的信息不重复问。
   用户确认对象后可用原话加 `--context -` 传 `{"answers":{"feeling_scope":"页面"}}`（值为候选 `applicable_when` 内的对象，如页面/按钮/后端），或在下一次原话中带上对象。不要因使用了候选就推定暗色、玻璃、渐变、技术栈或示例数字；`output_cost` 仅报告字符，不是宿主 token 成本。
4. 优先复用 `delivery.scenario_plans` 的流程、输出结构、验收项，不重新推导整套方案。流程固定，用户答案不固定。只有候选术语不足以完成任务；要把已确认要求、建议方向、未知边界和验收一起交付。
5. 使用已输出的 `matches + dependencies`；`contract_ref` 必需协议已由组合器加载并去重。`related` 只是相关信息，禁止全部展开。互斥布局只能作为备选，不合成未经确认的主布局。
6. `needs_staging` 时按 `composition.deferred` 分阶段或缩小范围，不能偷偷丢掉性能、降级、减少动态、来源或平台约束。`needs_verification` 不得转述成确定的供应商事实。
7. 无覆盖就承认。宿主确实能理解未命中的改写时，先用同一入口 `--catalog "信息 留白" --catalog-domain digital-product-uiux` 等小范围术语探索（目录结果会标明领域/子域，避免把图像构图条目当成界面规则）查出既有 ID（只显示名称/ID，不是检索成功证据，不 grep 整个知识库），再按[结构化调用契约](references/routing-contract.md)补充已知条目 ID、原文证据与建议身份，重跑原话。每个请求最多 2 次有针对性的 catalog 查询与 1 次语义候选重跑；仍不足就澄清/承认覆盖不足，不反复换词搜索或更改候选角色碰运气。多分句证据可以引用完整原话。通过 `--context -` 从 stdin 传 JSON，不落盘。不要只改写成专业词后丢失原始证据。无效 context 先报告原因，再无 context 重跑原话；禁止猜不存在的 ID 或无限改写搜索。
8. 用户确认必要信息后，按场景结构输出增强提示词与验收清单。`ready` 不是产品实现验收；完整宿主语义理解和执行能力需要单独测试，CLI 测试不能代替。

只将实际需要的结果交给模型，不把 `index/` 或 `terms/` 全目录塞入上下文。内部扫描索引不是模型上下文加载。无覆盖时仅在用户允许后做网络补充；临时搜索结果不自动写回知识正文。

## 知识类型

叶子包用 `knowledge_type` 区分：

- `term`：专业术语和白话解释
- `pattern`：可复用的设计/架构模式
- `technique`：实现技巧和参数锚点
- `guideline`：可访问性、质量和边界规范
- `parameter`：设计或运行参数
- `template`：可直接投喂给 AI 的提示词模板
- `platform-research`：平台专属研究，必须标注范围和核验状态

没有匹配到术语包时，说明覆盖不足；只有在用户允许时才进行网络搜索。搜索结果是本次临时参考，不写回术语列表。

## Dashboard 三层规范（合并分类）

Dashboard 布局变体优先放进已有 逻辑资源 `terms/dashboard/layout-patterns.json` 的条目，不为每个配色、场景或布局再建索引叶子。命中后只取当前条目，使用 CLI 已按 `contract_ref` 解析的共享协议；手动加载时用入口 `--resource <逻辑引用路径> --format agent` 读取，避免重复；视觉方向复用已有相关叶子，仅在需要时加载，不展开全部变体。目录显示的摘要来自原文；当用户只问某种状态同步或交互关系时，可读取候选条目的 `state / agentExec` 作为局部参考，不必连同布局、配色和示例参数整体套用，也不能只凭布局名字就断言没有相关知识。

按 `layout / termSkill / uiSkill / agentExec / state / tokens` 输出：术语定义信息结构，UI 定义视觉与栅格，Agent 定义交互状态机。分清共享状态与独立状态，写清每个事件改变什么、不改变什么，以及派生视图和验收断言。示例配色、比例和像素值不是全局默认值。

本轮按已有的 5 种布局完成素材整理，不要求补充额外案例。条目 `evidence` 保留原文与建议的区别；模板 `source_gaps` 仅记录实际实现阶段需要确认的业务规则，不是素材整理待办。暖色三栏可复用已知视觉并收录建议交互，但不能把候选房间联动或模式/单位映射当作已确认事实。

## AIGC IP 模板

当请求涉及同一角色的多种材质、动作、表情或周边时，先用入口 `--resource templates/aigc/base-ip.json --format agent` 读取，再按场景读取一个具体 `templates/aigc/*.json` 引用。合并基础 IP、一致性约束、场景模块和目标工具参数；不要把七个场景全部加载到同一次请求中。中文文字建议预留排版区域，由后期工具叠加。

逻辑资源 `terms/character-ip/character-ip.json` 只负责角色一致性和场景路由；镜头、构图、运动、负面约束和工具适配分别从对应子域加载。

## 交互、视觉效果与工具适配

连续交互和高级手势一次只加载一个模式。先读状态机、动画序列、触发阈值、空间锚点和取消/回退路径，再读可测参数、可访问性和验收标准；不要把整组交互一次性塞入上下文。遇到“细腻”“顺滑”“有质感”等感觉时，优先输出可观察的时间、速度、位移、旋转、缩放、吸附和先后关系。默认要求动画可中断、键盘和触摸结果一致，并遵守 `prefers-reduced-motion`。

视觉效果必须和性能一起加载。液态玻璃、景深、圆柱卷收、取色光晕和液态粘连都要同时读取 `performance_budget`、`fallback`、`mobile_degradation` 和 `reduced_motion` 字段；如果设备能力不足，先降级表现再保证主任务可用。

GSAP 适配只在用户明确指定 GSAP，或项目已经依赖 GSAP 时加载。优先使用工具对应叶子的生命周期、SSR 边界、`ctx.revert()`/销毁规则和 transform 性能约束；未指定 GSAP 时不要主动引入它。

设计系统预览优先加载 `living-style-guide-preview`，用 Light/Dark、token、组件状态和视觉验收清单指导实现。外部预览站、厂商文档和示例仓库必须保留 `verification_required`，未核验时只能作为参考线索。

## 平台研究边界

`platform-research` 叶子包只记录指定供应商或项目的研究信息。若 `verified_at` 为空，必须把内容说成待核验信息，不得推广为所有 GPU UI 框架或所有平台的通用事实。

# 用户效果复审：预先固定的验收方案

基线 `c42dd4a`。开始前工作区干净并完成 `git pull --ff-only`，不建分支、不使用 worktree、单执行者完成代码审查。真实宿主作为被测系统顺序调用，不承担审查/实现任务。

## 已复现风险

1. 否定范围处理：`不用 GSAP，要让网页有质感` 丢失正向需求；`不是 GPUIX` / `不依赖 GSAP` 未排除供应商。
2. 检索证据范围：跨分句的后端与椅子“稳定”、非软件洗衣间并发、小说情节“重复提交”被错拼。
3. 快路径只看已命中的场景，遗漏同句的毛绒玩偶非场景请求；同句未覆盖任务可能被整体判定已覆盖。
4. 澄清与完成契约：布局选择问题返回的 slot 不能回填；任意 `source:*` 都被接受；来源相关问题污染其他场景；非对象的多个模糊词没有澄清。
5. 分发：实际运行 `npx skills@1.7.4 add <local repository> --skill feeling-to-jargon --agent codex --copy -y` 成功后只安装 SKILL.md，脚本/知识/文档引用均在安装包外。
6. 成本：真实 Codex 宿主可恢复隐喻，但原始输出与无边界的全文检索增加工具上下文；完整用户配置还带入大量与本 Skill 无关的背景，必须分开计量。

## 最小架构修正

- 不增加叶子；修复否定/分句与元数据作用域，让组合证据有可解释边界。少量缺失动作同义词仍在已有条目维护，保留盲测失败而非无限补词。
- 明确快路径守卫：不能跳过同一需求中的非场景信号；内部元数据检查与实际正文加载分开报告。
- 完整输出保持兼容，新增宿主紧凑输出：原文/约束/依赖不裁剪，只去重解释与诊断；新增有限 catalog 让宿主发现既有 ID，不再 grep 全文知识库。
- 生成可分发的只读运行包，正文仍在原叶子唯一维护；包与契约为可校验构建产物，非第二份手工知识。安装启动器以 SKILL 位置定位资源，不能依赖消费项目 CWD。直接从 ZIP 读取，不解包、不新增服务/向量库/持久缓存。
- 回填 slot 必须对应真实问题；互斥主布局的选择可往返，来源问题只影响自己的场景。

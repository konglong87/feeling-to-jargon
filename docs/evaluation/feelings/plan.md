# Feeling-first review, 2026-10-21

## Audit/baseline
Frozen `before.json` records raw CLI full results and compact size for 20 short inputs before this change. Existing route rules frequently require an object and feeling in one clause; vague/no-match delivery supplies a question without any terminology. This misses the main product value even though installed-host interpretation can recover some cases.

## Minimal architecture
1. Keep canonical bodies/IDs, scenarios, composition, budgets and provider gates unchanged.
2. Add bounded **terminology previews**, not more leaves or bulk body loading. Author optional `retrieval.feelings` alongside the owning entry; reuse the existing conjunctive evidence matcher. Each cue selects terms already present in canonical name/parameters/definition (validated), not independent new knowledge. Generator projects the same metadata.
3. A bare, short feeling yields source-backed **conditional suggestions** with applicability and one scope question before implementation. The same cue with an explicit matching object can seed existing routing/composition. Nonmatching objects, negated cues and unrelated clauses must not inherit another domain's scope.
4. Existing loaded matches also expose readable `candidate_terms`; previews explicitly say whether their full body was loaded. Distinguish the user's literal feeling from an inferred professional direction; never present numeric defaults or uncalibrated probabilities as conclusions.
5. Bound preview directions/terms/text centrally. Report candidate envelope cost separately from canonical body budget and total serialization; full and agent must preserve identical term candidates. No vector DB, added service/model, dependencies or leaf reclassification.

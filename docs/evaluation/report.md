## 不只是增加召回

- 四个场景产出“已有证据 → 需要的信息 → 组合知识 → 输出结构 → 验收来源”。明确要求与建议分栏：大量用户只建议核对并发，稳定不自动加载幂等/扩展。
- 可撤销删除组合可访问性与原路径/减少动态约束；原索引插回条件满足时才增加 FLIP。示例时间不是用户答案；原话已给 5 秒则不重复询问窗口。
- Dashboard 复用原 `contract_ref`，两个备选布局只输出一次共享协议；不加载十套审美配方。未经确认的互斥主布局不能混合。
- 视觉效果保留性能、降级、移动端与减少动态字段；缺字段或依赖环直接拒绝该组合。放不下必需组合时返回 `needs_staging`，不交付“仅外观”的缩水答案。
- GPUIX/GSAP 等受供应商门控；原话否定优先于项目 context。未核验的平台事实返回 `needs_verification`，不能标成最终方案已就绪。
- 松散 `related` 不展开。知识原文单一维护，生成器产生检索投影并检测漂移。

## 快路径与通用路径对照

18 个预先标明场景的用例，两条路径的候选集合、必需约束、叶子/条目/正文量和交付计划一致。快路径把 runtime 路由评分从 **105 次降到 0 次**，但仍检查 **120 条生成检索记录**，并非零扫描、零 IO。

全组快路径启用/禁用的 CLI 中位数为 **30.45 / 30.32 ms**；内部路由中位数为 **4.774 / 5.089 ms**。差异很小，不宣称显著性能提升。此轮可验证的收益是减少重复 runtime 评分、显式复用场景流程、保持完整约束；尚不能量化真实 LLM 少推导多少 token。

## 回归与故障注入

- 22 个原有场景和 105 个标题 Top 1 检查通过（仅兼容性指标，不代表白话效果）。
- 原有 10 项 Dashboard 测试通过，包括单条预算、合并叶子、保留手工内容和生成幂等。
- 新增 10 组用户效果测试：30 固定输入、同组通用路径、依赖/去重/条件引用/互斥、数量与字符预算、平台否定、已知答案、host JSON、缺失强制字段与循环依赖。
- 宿主候选未知 ID、伪造证据片段、未知 slot/provider、原话数值冲突会被拒绝；无关的页面加载时间与被否定的时间不会充当撤销窗口。这里只是接口模拟，不是完整 Agent 验收。
- 索引一致性、检索投影与来源一致、依赖图、场景结构、Python 解析、Skill 校验与公开内容检查另行执行。

## 未见改写与剩余边界

实现后另外运行 6 条没有写入映射的完整改写。5 条正确找到既有方向：服务宕机、用户一起涌入、两次保存、网页层次、误删与键盘。

**“网站像赶集，眼睛没地方落。”仍返回覆盖不足。** 没有为这条盲测临时补词；它体现隐喻/开放域理解的边界。可由真实宿主按受约束接口提出候选，再核对原话；但该真实 LLM 流程还未验证。

多分句覆盖检查也只是启发式，不能证明全句每个含义都理解了。输出明确 `whole_request_semantics_verified=false`。`ready` 是可组织方案，不是业务产品实现已验收。

下一步值得做的是盲测更多真实用户改写、真实宿主多轮验收、采样评审未知/否定/跨句歧义，以及收紧解释外壳的输出成本；不是继续增叶子或堆同义词。

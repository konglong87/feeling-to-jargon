# 用户效果优化：审计、最小架构与验收方案

## 审计基线

基于 `4b18825`，先固定 `tests/fixtures/user-outcomes.json` 的 30 个用例，实际 CLI 输出与测量保存在 `baseline.json`。未调用宿主 LLM，不能由 CLI 结果推断完整 Agent 成败。

复现结果：专业后端词命中三个叶子；大型后端/稳定、并发白话、重复提交白话、有质感、页面杂乱等输入无结果；工业分区可定位。另有否定 GSAP 仍召回 GSAP、Metal 自动带入 GPUIX、普通移动端降级带入 GPUIX 等边界错误。现有 22 个场景、10 项 Dashboard 测试均通过，证明旧回归不足以代表真实效果。

当前顺序是 root + runtime → 路由扫描/裁剪 → 读取命中领域与意图索引验证归属 → 读取叶子/筛选条目。五级体系是组织结构，不是先后遍历的语义模型。现有分数是启发式排序，不是概率。`related` 混有松散关联、类别名称与条目 ID，不能直接全部作为必需依赖加载。

## 最小架构与取舍

1. **知识组织不变**：19 个领域、105 个叶子；正文只由原叶子维护。`aliases`、`plain_language`、`when_to_use` 生成条目检索投影。确实缺少的组合白话信号只写在对应条目的 `retrieval` 元数据中，不另维护关键词库。
2. **可解释检索**：保留既有词法评分，新增有正反条件的有限证据匹配；记录真实命中片段、来源字段、明确要求/建议方向。只识别有证据的属性；大量用户不自动等于峰值并发，稳定不联动所有后端质量属性。否定条件与供应商范围优先。
3. **场景流程**：四个轻量配方（后端质量澄清、视觉表达、可撤销删除、Dashboard 联动）只引用稳定 ID，不复制知识。固定信息收集→知识组合→输出→验收，不固定美术风格、栈或性能数值；部分覆盖保留已知部分，通用知识可独立回退。
4. **组合与预算**：`contract_ref` 自动解析共享协议；少量 `composition` 元数据表达必需/条件补充/互斥。保留整条正文及性能/降级/减少动态字段，依赖去重且保留来源。数量与字符预算一起检查，放不下的原子组合进入分阶段计划，不能冒充完整交付。
5. **宿主边界**：CLI 不调用模型、不宣称真正语义检索。可选结构化宿主输入只能引用已知 ID，明确证据片段与建议身份；提供可校验输入/输出、无效输入拒绝和本地回退契约。完整宿主工作流本轮不冒充已验证。
6. **真实执行顺序**：生成的检索投影/场景匹配 → 明确场景短路或通用词法回退 → 归属验证 → 组合 → 预算/交付检查。内部读了索引不等于将索引送入模型；分别报告实际文件读取、候选评分数、输出正文量与路由耗时。

不用向量库、外部服务、新依赖、额外模型、分类组合枚举或大规模叶子合并。已有 Dashboard 五种变体保留；独立状态机/验收边界的叶子不因只有一条内容而合并。

## 执行与验收顺序

1. 固定基线、用例和预期边界（已完成）。
2. 实现数据驱动检索与四个场景配方，扩展已有生成器，不改正文事实。
3. 独立组合器落实依赖、平台边界、去重和原子预算；CLI 保留原有字段并增加解释/交付结构。
4. 同组用例 before/after + 同义改写 + 负例 + 模糊/覆盖不足 + 组合预算；保留关键原始输入输出。与关闭快路径的运行比较质量、实际加载和扫描/耗时，不假设必然提速。
5. 执行全部旧回归、标题可达性、生成幂等、来源/引用校验和宿主契约的模拟输入测试。核对文档与实际执行；测试通过后提交 push，并查看实际发布的说明。

评价分别报告：必需相关候选召回、指定禁止项误召回、澄清/覆盖不足判断、依赖完整性、叶子/条目/字符量与时间。固定用例只是回归集，不代表开放域泛化；模拟宿主输入只验证协议，不能代表模型理解质量。
